# Echelon Commander — симулятор боя для ГМ

_Прежнее название — WarSim._

Настольное приложение (Windows) для мастера варгейма или ролевой войны: шаблоны подразделений и конкретные силы сторон (потери боя закрепляются за ними), пошаговый расчёт боя двух сторон с журналом причин и массовое моделирование для балансировки. Подходит для любой эпохи — от отряда в 2–3 бойца до полков в тысячи человек: всё, что влияет на расчёт, задаётся в наборе правил и редактируется в программе.

## Возможности

- **Понятная навигация.** «Главное» — первая страница: цепочка «Наборы правил → Шаблоны → Силы → Сценарии → Бои» со счётчиками и кнопками создания, незавершённые бои («Продолжить»), быстрый запуск сценариев и недавно изменённое. Навигатор слева — дерево: поиск и «+ Создать» сверху, разделы в порядке работы («Игра»: Сценарии, Бои; «Подготовка»: Силы, Шаблоны, Наборы правил) разворачиваются на месте, «+» у раздела создаёт объект, а щелчок по названию открывает **каталог раздела** — таблицу с поиском, группами и действиями прямо в строке (бой, прогоны, силы по шаблону, дублировать, сохранить в файл, удалить); у сценария шапка с «▶ Начать бой» всегда на виду, а быстрые переходы ведут к обстановке, участкам, сторонам, плану и соотношению сил; вкладки открытых объектов сверху, как в браузере (сжимаются, а не поместившиеся — в списке «▾»), не копятся: щелчок в навигаторе открывает вкладку-просмотр, которую заменяет следующий объект, пока с ней не начали работать; вкладки можно закрепить, закрыть другие или справа (правый щелчок), а сверх предела давно не используемые закрываются сами; кнопки «назад / вперёд» (Alt+← / Alt+→, боковые кнопки мыши); над заголовком каждой страницы — где вы находитесь. Окно без системной шапки: кнопки окна встроены в верхнюю полосу.
- **Быстрый переход и отмена.** Ctrl+K находит любые силы и шаблоны (в том числе вложенные части — откроется с выделенным узлом), сценарий, тип или раздел набора правил, бой и команду. Ctrl+Z / Ctrl+Y отменяют и повторяют любые правки, включая удаления. В конструкторе работают стрелки, Ins, Ctrl+D, Del и F2.
- **Работа с клавиатуры:** Tab проходит по пунктам навигатора, строкам списков и записям журнала с разбором (Enter открывает, ↑/↓ — соседний пункт); меню «⋯» открывается Enter или ↓, пункты выбираются стрелками, Esc закрывает и возвращает фокус; подсказки «?» показываются при переходе на значок клавишей Tab; Esc закрывает окна и диалоги.
- **Наборы правил под эпоху:** классы целей, дистанции, каталог типов (люди, расчётное вооружение, техника) с огневой мощью по классам и дистанциям, приказы, уровни опыта и командиров, условия боя (местность, время суток, погода — и свои категории), укрепления, разведданные, свои правила вида «если… то характеристика ×N» (в том числе по состоянию: мораль, подавление, потери элемента и стороны), заготовки временных эффектов (дым, внезапность, растерянность…), уровни исхода, около 100 коэффициентов и порогов. Типы, приказы, условия, правила и эффекты переносятся из другого набора; при смене набора у шаблона или сил типы состава сопоставляются (заменить, добавить в набор, убрать). Ненужные механики (топливо, связь, поломки…) выключаются галочкой. В комплекте два примера: «Универсальный» (XX–XXI век) и «Линейная тактика» (XVIII–XIX век) — у каждого есть свои шаблоны, силы и готовый сценарий («атака на высоту 212»; «бой у переправы»: пехотная бригада с батареей и гусарами против батальона за редутами с батареей и кирасирами в резерве, с планом ввода резервов — исход не предрешён, около трети побед атакующих).
- **Шаблоны — штатное устройство:** единое дерево любой глубины — от бойца до армии; что это за звено, говорит само название («1-й взвод», «копьё», «полк»). Два вида: **оргсхема** и **список**. У любого узла — состав по штату (типы из каталога) и подчинённые; эшелон, штаб, атака и защита в %, теги. Приказа и состояния у шаблона нет — он нужен только для того, чтобы создавать по нему войска. Шаблон вставляется в другой как связанная копия (сразу ×N с нумерацией: «1-й взвод», «2-й взвод»…); если шаблон изменился, копии помечаются и обновляются по одной или все сразу. Сводка: численность, техника, огневая мощь. Набор правил виден и меняется прямо в редакторе; пустой шаблон подсказывает, с чего начать.
- **Силы — конкретные подразделения сторон:** создаются по шаблону («Создать силы по шаблону…» ×N, «+ Новые силы», прямо из сценария) и сгруппированы по командам (сторона, страна, отряд) — у команды свой цвет и название, которое можно сменить. У сил своё состояние — в строю, раненые и техника в ремонте, опыт, мораль, слаженность, готовность, боезапас, топливо, снаряжение, усталость, связь, снабжение; всё **наследуется от старшего**, пока не задано явно. Потери боя записываются в конкретные силы, а не в шаблон, которым пользуются все: батальон, потрёпанный в первом бою, во второй выйдет с некомплектом. Между боями — **отдых** (состояние бойцов в строю — к норме на заданный процент), **лечение** раненых, **ремонт** техники и **пополнение** из резерва или из другого подразделения; всё это и бои с исходом и потерями — в **боевом пути** сил; по желанию опыт растёт после N боёв. Если шаблон изменился, силы предлагают обновиться — устройство и штат берутся из шаблона, названия, потери и состояние сохраняются. Часть сил (или силы целиком) можно **временно передать в другое подразделение** — со всем составом, потерями и состоянием; она воюет в его составе, сценарии сами ссылаются на новое место, а «Вернуть» ставит её на прежнее место. Командиров нет ни в шаблонах, ни в силах — они задаются в сценарии и в бою.
- **Сценарий:** две стороны и сколько угодно сил на каждой — «+ Добавить на сторону…»: готовые силы целиком или **только нужные части** (рота из батальона, батальон из бригады — с состоянием старшего) либо новые силы по шаблону ×N; перетаскиванием из навигатора. Одно подразделение не участвует в сценарии дважды — программа предупредит. **Приказы задаются в сценарии** — у подразделения на стороне и при желании у его частей. Силы, перетащенные на другие, придаются им на этот бой («отделить» — вернуть). У подразделения на стороне можно снять галочки с частей, которые в этом бою не участвуют, не меняя сами силы, а для малых операций — выделить в бой **неполный состав**: сколько каждого типа идёт в бой, вплоть до одного бойца или одной машины (из отделения — трое, из взвода — один танк); остальные остаются в силах, потери боя ложатся на всё подразделение, а мораль и усталость меняются на долю участвовавших. Укрепления и разведданные, задачи сторон (удержать, захватить, нанести потери, сохранить силы, разведать, не допустить бегства), условия, начальная дистанция, **ширина фронта**, **длительность боя в часах** (ходов — сколько укладывается при длине хода набора правил; «удержать позицию» тоже в часах и выполнена, если срок выдержан, даже если позицию оставили позже; в итогах, прогонах и прогнозе время — тоже в часах), «стоять насмерть» у подразделений и частей на этот бой, соотношение сил. **Участки боя** (фланги, высота, деревня): у каждого своя дистанция и сближение, при желании своя местность, укрепления и ширина фронта; подразделения и их части назначаются на участок; наблюдение и прямой огонь — в пределах участка, артиллерия достаёт соседние; переброски нет. **Огневая поддержка** вне поля боя (артиллерия старшего начальника, авиация): тип из каталога × число единиц, сколько ударов за бой.
- **Пошаговый бой.** Каждый ход: события плана боя → доведение приказов ГМ → обнаружение → удары огневой поддержки → инициатива → огонь и выбор целей → потери → подавление → движение → боезапас, топливо, поломки → усталость → мораль и слаженность → проверки (уничтожение, паника, отход, потеря штаба, распад формирования, ввод резервов). Между ходами ГМ меняет приказы, условия, дистанцию (по участкам), состояние и состав элементов, снабжение, вводит подкрепления раньше плана, накладывает **временные эффекты** на сторону, формирование или отмеченные элементы, вызывает **удары огневой поддержки**; отмеченным галочками элементам — **групповые решения** разом. Всё записывается в журнал и воспроизводится. **«⏭ До события»** считает ходы, пока не случится важное (бегство, потеря штаба, ввод резерва, смена дистанции, событие плана, большие потери — настраивается). **«Прогноз»** — сотни продолжений боя с текущего хода: вероятности исходов и потерь, с только что принятыми решениями и без них. **«Ответвить бой…»** — копия с выбранного хода, чтобы сыграть иначе и сравнить. Любой ход и решение можно отменить (↶, Ctrl+Z на вкладке боя) или вернуться к концу любого хода — бой повторяется с теми же бросками.
- **Правдоподобные исходы.** Перевес решает постепенно, а не «по квадрату»: в огневой контакт одновременно вступает не больше сил, чем позволяет **ширина фронта** (охват по силам противника и при желании ширина в метрах), остальные — вторая линия и стреляют слабее. Каждой стороне в начале боя выпадает **удача и исполнение** — множитель огня и стойкости («день» стороны: внезапность, слаженность, ошибки). **Приказы ГМ доходят не сразу** — шанс за ход зависит от связи и командира; в таблице сил видно, какой приказ в пути. Модель откалибрована: атака на подготовленную оборону при 1:1 почти всегда срывается, при 2:1 удаётся примерно в половине случаев, при 3:1 — в четырёх из пяти, атакующий при этом теряет больше; подразделения ломаются в среднем при трети потерь. Это закреплено тестом баланса. Бои, начатые до этих механик, повторяются и продолжаются по прежним правилам.
- **План боя** в сценарии: подход подкреплений, смена приказа (ввод резерва, отход), смена условий (ночь, дождь), удар огневой поддержки (артподготовка), временный эффект — на заданном ходу (с вероятностью и разбросом) или **по условию**: потери, выбыло, мораль стороны или подразделения, дистанция — с задержкой («когда потери Красных ≥ 30%, через ход — контратака резерва»). Работает и в бою, и в массовых прогонах, где ГМ не вмешивается.
- **Журнал с объяснениями:** у каждой записи о потерях, морали, обнаружении, инициативе и проверках есть разбор множителей («Приказ «Атака» ×0.75, Холмы ×1.1, Подавление 34% ×0.8…»).
- **Командиры — решение ГМ, а не шаблона:** командир есть у каждого формирования, имена не нужны. Стартовый уровень (от «некомпетентного» до «выдающегося» или «без командира») задаётся в сценарии («Командиры в начале боя») — так и массовые прогоны моделируют сильного или слабого командира; по ходу боя ГМ меняет его в таблице сил — удачное решение или ошибка в конкретный момент. Всё пишется в журнал и воспроизводится.
- **Большие бои читаемы:** одинаковые имена уточняются старшими («2-й взвод · 3-я рота»), потери и мораль за ход сводятся по формированиям, таблица сил и оргсхема сворачиваются, у групп — итоги ветки.
- **Итоги:** потери людей (убито / ранено / пропало) и техники по типам (уничтожено / повреждено / брошено), остаточная боеспособность, организация, мораль, снабжение, выполнение задач, уровень исхода со строкой «Решило: …», ключевые события, разбивка по формированиям, графики по ходам. Полный отчёт — для ГМ; **донесение для каждой стороны** — свои цифры точно, противник диапазоном по уровню разведданных (туман войны). **«Записать итоги в силы»** — потери, раненые и техника в ремонте, мораль, усталость и боезапас на конец боя переходят в силы, участвовавшие в бою (для кампаний); повторная запись — только с подтверждением, Ctrl+Z отменяет.
- **Массовое моделирование:** N прогонов сценария — вероятности исходов, средние потери, медиана, 10–90%, мин–макс, гистограммы, список прогонов с сортировкой; любой прогон открывается как полноценный бой. Экспорт CSV. **Сравнение вариантов**: перебор одного параметра (командир, разведданные, укрепления, условие, начальная дистанция, приказ, ход события плана, число ударов поддержки) или сравнение с другим сценарием — с одними и теми же случайностями, чтобы разница была от параметра.
- **Случайность и повторы:** каждый бой случайный; «Переиграть» — новый бой, «Повторить этот же бой» — те же броски кубиков (с вашими решениями или без).
- **Бои занимают мало места:** на диск пишется журнал без подробного уровня и разборов (в 7–9 раз меньше: бой дивизия на дивизию — около 1,5 МБ вместо 11); подробности восстанавливаются повтором боя, когда их открывают. Все бои сценария, завершённые или вообще все бои удаляются разом (навигатор, настройки).
- **Новый набор правил** создаётся на основе существующего (по умолчанию — того, с которым работаете) или пустым.
- **Данные — JSON-файлы** в папке данных (по умолчанию «Документы/Echelon Commander», у портативной версии — папка `Echelon Commander-data` рядом с .exe; если от прежней версии осталась папка «Документы/WarSim» или `WarSim-data`, программа продолжает работать с ней; шаблоны — в `formations/`, силы — в `forces/`): их можно копировать, передавать другим ГМ (экспорт/импорт) и править вручную. Версия данных хранится в самих файлах: обновления данных прежних версий выполняются один раз и не повторяются при переносе папки на другой компьютер.
- **Защита данных.** Наборы правил, шаблоны, силы и сценарии автоматически копируются в `backups/` при запуске и раз в час, если что-то изменилось (хранятся 10 последних копий и по одной за 14 дней); копию можно сделать и вернуть в Настройках — текущее состояние перед этим само сохраняется. Удалённое (включая бои) попадает в корзину `trash/` на 30 дней и возвращается из Настроек или кнопкой «Вернуть» в уведомлении. Файл, который не читается (повреждён, пуст), не теряется: он откладывается в `damaged/`, остальное загружается, а программа сообщает об этом и подсказывает, где взять копию.

## Как получить .exe

Сборка для Windows выполняется автоматически в GitHub Actions (workflow «Сборка»): откройте последний запуск во вкладке **Actions** репозитория и скачайте артефакт **EchelonCommander-windows**. Внутри два файла:

- `EchelonCommander-<версия>-setup.exe` — установщик;
- `EchelonCommander-<версия>-portable.exe` — портативная версия без установки (данные хранятся в папке `Echelon Commander-data` рядом с файлом).

Собрать самостоятельно на Windows (нужен Node.js 22):

```
npm ci
npm run dist:win
```

Готовые файлы появятся в папке `release`.

## Разработка

```
npm ci            # зависимости
npm start         # собрать и запустить настольное приложение (Electron)
npm run dev       # интерфейс в браузере (данные — в localStorage), с горячей перезагрузкой
npm test          # тесты движка и баланса (tests/balance.test.ts — правдоподобие исходов на стандартных боях)
npm run test:e2e  # проверки интерфейса в браузере (Playwright; первый раз: npx playwright install chromium)
npm run typecheck # проверка типов
npm run lint      # линтер (Biome)
npm run format    # форматирование (Biome)
npm run check     # линтер и форматирование без исправлений — как в CI
npm run sim       # демо-бой в консоли; npm run sim -- сценарий.json правила.json --runs 500
```

### Устройство

```
src/engine/   движок боя — чистый TypeScript без зависимостей от интерфейса
  types.ts          модель данных (правила, подразделения, сценарий, состояние боя, итоги)
  forces.ts         шаблоны и силы: создание по шаблону, ссылки сценария на силы, запись итогов боя, отдых, пополнение
  control.ts        «ход до события» и прогноз с текущего хода
  variants.ts       варианты сценария для сравнения в массовом моделировании
  transfer.ts       перенос между наборами правил, сопоставление типов
  units.ts          дерево подразделений: наследование, шаблоны и их обновление, перемещение
  coefficients.ts   описание всех коэффициентов и порогов с значениями по умолчанию
  defaults.ts       наборы правил-примеры, фабрики, демо-данные
  context.ts        система модификаторов и справочники
  battle.ts         создание боя и порядок фаз хода
  phases/           фазы хода: events (план боя), orders (доведение приказов), detection, initiative, fire (огонь и удары
                    поддержки), frontage (ширина фронта), movement, upkeep (снабжение, усталость), morale, checks, end
```
